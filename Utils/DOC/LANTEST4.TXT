1.     Functional Specification

1.1    Introduction - requirement

1.1.1  The primary requirement of the LAN test is to confirm that all
       elements of the ECCO+ office installation are functioning 
       correctly with respect to the LAN capabilities of the system.
       
       If it is found that the LAN is not functioning correctly, then 
       the secondary requirement of the LAN test is to determine which
       element of the system is at fault.

1.1.2  The LAN test will consist of a set of computer programs and 
       operational procedures which will allow the testing of:
       
       a)  the LAN wiring (ie the LAN T-box, interconnecting cables and 
           stub cables);
       b)  the counter terminal (CT) and back office system (BOP) LAN 
           hardware.
       
1.1.3  The programs and procedures will be simple and unambiguous so
       that PO staff may carry out the tests without requiring extensive
       computing experience.  In particular, the 'pass/fail' decision 
       will not require a subjective judgement from the operator.

1.1.4  Hardcopy confirmation of the result of the test will be provided
       in the form of a printout from the CT printer.


1.2    Background - LAN operation overview

1.2.1  The LAN functionality is provided by the multi-port comms card 
       in the CT or BOP, and by the LAN software (LANLink) and the
       operating system (PCMOS).

       The daisy-chain topology of the network means that the end CT
       (CT.21 in the diagram above) has to communicate with the BOP via 
       all active intermediate nodes.  When this happens the CT initiates 
       the activity and the intermediate nodes carry out "passthru" of 
       the message.  A message from the CT travels to its adjacent
       neighbour, from there to the next CT, and so on until it goes from 
       CT1 to the BOP.  Thus the message has had to travel through every 
       LAN cable and every CT comms card in the office.

1.2.3  Performance

       Under controlled conditions, the performance of the LAN is
       consistent and predictable.  The transfer rate (throughput) of 
       information between a given CT and the BOP is fixed and easily 
       measurable.  Due to a small performance overhead related to 
       passthru, the measured throughput at a CT is dependent on its
       position in the office.
      
       
1.2.3  Hardware

       The LAN ports of a CT or BOP are served by a DUART on the comms
       card.  The integrity of the DUART may be determined by an 
       internal loopback test.  The DUART, the driver stages of the 
       circuitry, and the port on the distribution panel on the rear of 
       the CT or BOP can be tested using an external loopback test.  
       The external loopback test requires a loopback connector which 
       plugs into the LAN port on the distribution panel. 


1.3    Basic functionality

       Two types of diskette will be used; a CT diskette, and a BOP 
       diskette.  Two applications are to be run and these will be
       referred to as LANCT and LANBOP.  The BOP should be booted first
       followed by each CT in turn.

1.3.1  BOP functionality

       a)  The BOP is rebooted using the BOP diskette.
       b)  PCMOS loads and installs the system drivers, LANLink 
           drivers, and RAMDISK.
       c)  A file, say LANTMP, is copied from the floppy drive to the
           RAMDISK.
       d)  The LAN server is kicked off as a background task.
       e)  The LANBOP application is automatically run in the foreground.
       f)  The operator is prompted to enter the number of counter 
           terminals in the office.  This information will enable the 
           overhead due to passthru to be taken into account. 

1.3.2  CT functionality

       a)  The CT is rebooted using the CT diskette.
       b)  PCMOS loads and installs the system drivers and LANLink 
           drivers.
       c)  The LAN server task is kicked off as a background task.
       d)  The LANCT application is automatically run in the foreground.
       e)  Three tests are provided by LANCT:
           - cable test;
           - throughput test;
           - loopback test;
       f)  To begin with LANCT automatically runs the cable test.  If 
           this is not successful the CT displays a failure message and
           the operator is advised to check the wiring.  A key press is
           required before the main menu is displayed.
       g)  If the cable test is successful then the LAN test main menu 
           is displayed on this CT.  
       h)  The LANCT main menu provides options to carry out a LAN 
           cable test, throughput test, and loopback test.
       i)  The LAN throughput test transfers the LANTMP file from the 
           BOP into the CT's memory and calculates the transfer rate.  
           This rate is compared with an expected rate and a pass/fail
           result is determined.  The result is printed automatically.
       j)  The LAN test result can be reprinted if required.  The 
           printout also shows the result of the cable and loopback test.

       consistent and predictable.  The transfer rate (throughput) of 
       information between a given CT and the BOP is fixed and easily 
       measurable.

       a small reduction in throughput.  The throughput achievable at

3.2    LAN test applications

3.2.1  LANTST.EXE

       LANTST.EXE will provide the following functions:
       
       a)  cable test;
       b)  throughput test;
       c)  loopback test;
       
3.2.2  an application, LANTST.EXE, to be run on the BOP.
       LANTST.EXE will provide an indication that the BOP is active
       on the LAN and will respond to requests from the end CT.
